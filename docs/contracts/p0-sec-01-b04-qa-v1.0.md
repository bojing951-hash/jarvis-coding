## B04-QA-01｜Docker Event 原始信息完整性

**前置：**

能够从真实 Docker CLI 获取结构化容器事件。

**测试动作：**

执行一次真实测试容器生命周期，采集原始事件。

**预期：**

每条必需事件必须包含：

- Type。
- Action。
- Actor.ID。
- 容器名称。
- 可信时间戳。

原始信息不得在验证之前被降维为事件动作集合。

不得在采集过程中丢失会影响身份、顺序或时间判断的重复事件。

**FAIL：**

只采集 Action，或未保存容器 ID、时间信息却宣称证据完整。

**证据：**

原始 Docker JSON Lines、采集命令、Docker 版本、执行退出码、原始日志文件及 SHA-256。

## B04-QA-02｜真实容器身份绑定

**前置：**

存在 Execution、Resource 和真实容器 ID。

**测试动作：**

使用正常事件、错误 ID、不同容器混合事件和错误容器名称，调用实际共用验证器。

**预期：**

所有必需事件必须属于同一个目标 Container ID。

该 ID 必须与本次实际观察的容器 ID 一致。

容器名称必须与 Resource 及 Execution ID 对应。

不同容器的事件不能拼接成单次合法生命周期。

**FAIL：**

任意非空 Container ID 即可通过，或混合不同容器的四个事件仍然 PASS。

**证据：**

真实 ID 映射、共用验证器输出、负向测试原始输入与失败原因。

## B04-QA-03｜生命周期顺序与时间

**前置：**

具有结构化且包含可信时间戳的 Docker 事件。

**测试动作：**

测试：

- 正常 create/start/die/destroy。
- 完全倒序。
- 部分倒序。
- 时间戳逆序。
- 时间戳缺失。
- 非法时间戳。
- 重复事件。
- 不同生命周期拼接。
- 无法确认时钟关系。

**预期：**

正常单次生命周期通过。

错误顺序、无效时间或无法证明属于同一生命周期的输入必须拒绝。

其他无关 Docker 事件可以存在，但不能被用于制造虚假的完整事件链。

**FAIL：**

倒序事件、时间逆序或无效时间仍被判定 PASS。

**证据：**

结构化事件、时间比较结果、共用验证器 failures。

## B04-QA-04｜取消时间与物理生命周期绑定

**前置：**

真实启动/取消竞态测试运行中。

**测试动作：**

记录：

- 取消请求。
- 启动屏障释放。
- Docker create/start。
- Docker die/destroy。
- 取消成功确认。
- 最终物理状态查询。

**预期：**

必须证明：

1. 事件属于本次 Execution。
2. 目标容器确实启动过。
3. 容器可信停止不晚于取消成功确认。
4. 最终容器清理状态真实可确认。
5. 不存在取消确认后的迟到执行副作用。

容器停止和容器销毁必须分别判断。

时钟无法可靠比较时，不得产生无依据的成功结论。

**FAIL：**

取消成功早于容器停止，或者无法核实时间关系仍判定 PASS。

**证据：**

时间线、事件记录、取消返回时间、容器状态、SQLite 状态及 Git 前后状态。

## B04-QA-05｜共用验证器反向测试

**前置：**

实际 evaluateDockerRaceEvidence() 可被测试调用。

**测试动作：**

注入以下异常：

- 事件完全倒序。
- 必需事件 ID 不一致。
- 混合不同容器的事件。
- 事件名称与目标 Resource 不一致。
- 时间戳缺失。
- 时间戳逆序。
- die 晚于取消确认。
- 缺少必要事件。
- 事件查询失败。
- 原始 JSON 解析失败。
- Docker ps/inspect 失败。
- 最终 Docker 仍 running。
- SQLite 状态不一致。
- Git HEAD 变化。

**预期：**

每个不满足必要证明条件的输入都必须返回明确 FAIL。

测试使用的判定函数必须与真实 Docker 验证脚本相同。

**FAIL：**

任意异常输入仍产生 validation.ok=true。

**证据：**

测试输入、实际共用函数、完整断言、测试结果及 failures。

## B04-QA-06｜旧失败与新通过

**前置：**

固定旧版：

`0a1828069f1dfdf913d0a5f917cb9ba910a90f69`

以及 B04 新固定版本。

**测试动作：**

分别验证：

1. 正常生命周期。
2. 完全倒序事件。
3. 无关联 Container ID。
4. 混合不同容器事件。
5. 时间信息缺失。
6. 取消确认与 die 时间关系错误。

**预期：**

旧版能暴露已知假阳性。

正常合法证据新版必须继续通过。

对于事件数据结构升级，应提供新旧测试语义映射及原始证据。

不能用旧版不支持新数据格式作为修复成立的证明。

**FAIL：**

无法区分新旧已知失败模式，或通过放宽断言制造成功。

**证据：**

两个固定 Commit、测试代码 Diff、独立运行记录。

## 最终裁决规则

B04 专项 FAIL：任何确定性阻断缺陷成立。

B04 专项 OPEN/WAITING：未发现确定性缺陷，但缺少必要独立证据。

B04 专项 PASS：八项补充验收全部满足且证据充分，没有未解决的相关阻断缺陷。

B04 专项 PASS 不代表 P0-SEC-01 整体 PASS。

P0 完整通过仍必须满足原 22 AC、10 E2E、15 EV 和适用补充契约。

封版、合并 main 以及风险接受权属于用户。

本契约一经 G0 提交冻结，不得开发后调整。
